# T8 — Money UI (invoices, payments, balances)

## Goal
A working Money section: invoice list, create an invoice, record a payment
against it, view invoice balance and job financials. Wired to
`co_create_invoice`, `co_record_payment`, `invoiceBalance`, `jobFinancials`
(+ `listJobs` for context).

## Dependencies
T1.

## Context
- The core is payments-AGNOSTIC by design: it records money events
  (invoices, payments) — no Stripe/Polar provider code lives here, and none
  should be added. Amounts are data, not checkout flows.
- Same app/auth/UI conventions as T5–T7. Money forms get extra care:
  amounts as integer minor units (or whatever the validator expects — read
  `backend.ts` first), no floating-point money math client-side.

## Acceptance criteria
- Create invoice → record payment → balance decreases, all against the real
  backend.
- Overpayment / invalid amounts are rejected (client validation + server
  validators).
- Zero payment-provider code added. This stays provider-agnostic.

## Out of scope
- Stripe/Polar/checkout integration. Dunning/reminders. Accounting export.
