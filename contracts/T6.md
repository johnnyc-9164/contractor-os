# T6 — Bids & proposals UI

## Goal
A working bidding section: create a scope, create a proposal from it, submit
the bid, convert a won bid to a contract, mark the contract signed. Wired to
`co_create_scope`, `co_create_proposal`, `co_submit_bid`,
`co_convert_bid_to_contract`, `co_mark_contract_signed` (+ `inspectRecord` /
`history` for detail views).

## Dependencies
T1.

## Context
- Same app/auth/UI conventions as T5. Read the mutation arg validators in
  `packages/backend/convex/backend.ts` before writing forms.
- The bid lifecycle is lead → scope → proposal → submitted bid → contract →
  signed. The detail view should show where a record sits in that lifecycle
  and offer only the valid next action(s).

## Files (8 max)
1. `apps/web/src/app/bids/page.tsx` — new: bids/proposals list (derive from
   `listLeads` detail or a dedicated query if one exists — check `backend.ts`
   first; do not invent a query that isn't there)
2. `apps/web/src/app/bids/[id]/page.tsx` — new: bid detail with lifecycle
   state + next-action buttons
3. `apps/web/src/components/bids/scope-form.tsx` — new (`co_create_scope`)
4. `apps/web/src/components/bids/proposal-form.tsx` — new
   (`co_create_proposal`)
5. `apps/web/src/components/bids/bid-actions.tsx` — new: submit bid
   (`co_submit_bid`), convert to contract (`co_convert_bid_to_contract`),
   mark signed (`co_mark_contract_signed`), each gated on lifecycle state
6. (optional) nav link addition
7. (optional) colocated loading/empty states
8. Nothing else — no new backend functions

## Verification (5 max)
1. `pnpm check-types` — exit 0
2. `pnpm exec biome check apps/web/src/app/bids apps/web/src/components/bids` — exit 0
3. `pnpm --filter web build` — exit 0
4. `pnpm test` — exit 0
5. Lifecycle gating self-review: each action button is disabled/hidden unless
   the record's current state permits it (cite the validator logic)

## Acceptance criteria
- Full bid lifecycle completable in the UI against the real backend.
- Invalid transitions are impossible from the UI (and rejected server-side
  by the core validators).
- No new Convex functions added — UI composes the existing domain API.

## Out of scope
- PDF proposal generation. E-signature. Pricing engine changes.
