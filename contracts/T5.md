# T5 — Leads pipeline UI

## Goal
A working Leads section: list all leads, view a lead (detail + history),
create a lead, advance a lead's stage, schedule a site visit. Wired to the
real domain queries/mutations (`listLeads`, `inspectRecord`, `history`,
`co_create_lead`, `co_advance_lead`, `co_schedule_site_visit`).

## Dependencies
T1 (domain functions deployed under the `api` the web app imports).

## Context
- Domain functions live in `packages/backend/convex/backend.ts` after T1;
  the web app imports `api` from `@contractor-os/backend/convex/_generated/api`.
- Auth: Clerk (`@clerk/nextjs`); existing patterns in
  `apps/web/src/app/dashboard/page.tsx` (`Authenticated` / `Unauthenticated`
  / `useQuery`).
- UI primitives: `packages/ui/src/components/*` (shadcn). Additive use
  only — do not modify existing primitives.
- Read `backend.ts` arg validators for exact mutation signatures before
  writing forms (via `graft ask` on the specific function names).

## Files (8 max)
1. `apps/web/src/app/leads/page.tsx` — new: leads list (`listLeads`)
2. `apps/web/src/app/leads/new/page.tsx` — new: create-lead form
   (`co_create_lead`)
3. `apps/web/src/app/leads/[id]/page.tsx` — new: lead detail
   (`inspectRecord` + `history`)
4. `apps/web/src/components/leads/lead-form.tsx` — new: shared form
   (create; reuse for edit if the domain supports it — if not, create-only)
5. `apps/web/src/components/leads/advance-lead.tsx` — new: stage advance
   (`co_advance_lead`) + schedule site visit (`co_schedule_site_visit`)
6. `apps/web/src/app/leads/[id]/page.test.ts` — hmm, prefer a pure-logic
   test if one exists (e.g. stage-transition labels); otherwise a second
   component file instead of a thin test
7. (optional) nav link addition in the existing header/shell
8. (optional) loading/empty states colocated with the above

## Verification (5 max)
1. `pnpm check-types` — exit 0
2. `pnpm exec biome check apps/web/src/app/leads apps/web/src/components/leads` — exit 0
3. `pnpm --filter web build` (or `turbo run build -F web`) — exit 0
4. `pnpm test` — exit 0
5. Every mutation call site passes args matching the validator in
   `backend.ts` (self-review the diff; note any `v.any()` looseness in the
   PR body)

## Acceptance criteria
- All five lead operations work against the real backend (no mock data,
  no dead buttons).
- Unauthenticated visitors see the sign-in gate, not the pipeline.
- Forms validate client-side (zod) AND rely on server validators.

## Out of scope
- Scope/proposal/bid UI (T6). Styling system changes. Landing page.
