# T7 — Jobs UI (execution, daily reports, subcontractors)

## Goal
A working Jobs section: job list, job detail, create a job, advance job
state (`transition`), submit daily reports, assign subcontractors, view job
financials. Wired to `listJobs`, `co_create_job`, `transition`,
`submit_daily_report`, `assign_subcontractor`, `jobFinancials`,
`inspectRecord`, `history`.

## Dependencies
T1.

## Context
- Same conventions as T5/T6. `transition` is the generic state machine —
  read its validator in `backend.ts` to learn the legal transitions before
  building the UI (never hardcode a transition list the server would reject).
- Daily reports and subcontractor assignment are the field-crew surface:
  keep forms short and mobile-usable (this app ships as a PWA).

## Files (8 max)
1. `apps/web/src/app/jobs/page.tsx` — new: job list (`listJobs`)
2. `apps/web/src/app/jobs/new/page.tsx` — new: create-job form
3. `apps/web/src/app/jobs/[id]/page.tsx` — new: job detail (state,
   financials via `jobFinancials`, `history`)
4. `apps/web/src/components/jobs/job-form.tsx` — new: shared create form
5. `apps/web/src/components/jobs/transition-controls.tsx` — new: legal
   next-state buttons (`transition`), driven by current state
6. `apps/web/src/components/jobs/daily-report-form.tsx` — new
   (`submit_daily_report`)
7. `apps/web/src/components/jobs/assign-sub.tsx` — new
   (`assign_subcontractor`)
8. (optional) nav link addition

## Verification (5 max)
1. `pnpm check-types` — exit 0
2. `pnpm exec biome check apps/web/src/app/jobs apps/web/src/components/jobs` — exit 0
3. `pnpm --filter web build` — exit 0
4. `pnpm test` — exit 0
5. Transition controls render ONLY states the server validator permits for
   the job's current state (self-review against `backend.ts`)

## Acceptance criteria
- Full job lifecycle in the UI against the real backend, including at
  least one daily report and one subcontractor assignment.
- Financials visible on the job detail page.
- Mobile-usable forms (PWA is a first-class target).

## Out of scope
- Crew scheduling calendar. Photo uploads (unless the domain already
  supports attachments — check first, don't invent).
