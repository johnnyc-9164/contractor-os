# T1 — Unify Convex backend into packages/backend

## Goal
Make `packages/backend` (the deployed Convex project) the single, real
backend. Today it is a hollow shell — empty schema, no components, missing
the two `@johnnyc2026` dependencies — while the entire domain backend lives
undeployed in `apps/web/convex/`. After this task, the domain functions are
deployed with the project and reachable through the `api` import the web app
already uses (`@contractor-os/backend`).

## Dependencies
None. (Wave 1 — runs parallel with T2, T3, T12.)

## Context (from the Graft map — verify before editing)
- `apps/web/convex/backend.ts` — 15 mutations (`co_create_lead`,
  `co_schedule_site_visit`, `co_advance_lead`, `co_create_scope`,
  `co_create_proposal`, `co_submit_bid`, `co_record_payment`, `co_create_job`,
  `co_convert_bid_to_contract`, `co_mark_contract_signed`, `co_create_invoice`,
  `execute`, `transition`, `assign_subcontractor`, `submit_daily_report`)
  and 7 queries (`componentInfo`, `history`, `jobFinancials`,
  `invoiceBalance`, `listJobs`, `listLeads`, `inspectRecord`), built on
  `@johnnyc2026/contractor-os-core`.
- `apps/web/convex/cms.ts` — facade over `@johnnyc2026/cms` (`createSite`,
  `getSite`, `listSites`, `updateSite`), every function gated by
  `requireIdentity`.
- `apps/web/convex/memberships.ts` — `contractorOsMemberships` table model,
  `set` is an internal mutation (owner-only; do not expose).
- `apps/web/convex/schema.ts` — the membership table + `by_identity` index.
- `apps/web/convex/convex.config.ts` — registers the `contractorOs`
  component (`MODE: development`) and the `cms` component. This is the config
  the deployed project must end up with.
- `packages/backend/convex/auth.config.ts` — Clerk auth config, already in
  place in the deployed project (it never lived in `apps/web/convex/`; no
  move needed — verify it stays untouched).
- `packages/backend/convex/` — currently `healthCheck.ts`,
  `privateData.ts`, empty `schema.ts`, empty `convex.config.ts`.
- Web app imports `api` from `@contractor-os/backend/convex/_generated/api`
  (`apps/web/src/app/page.tsx`, `apps/web/src/app/dashboard/page.tsx`).

   `@johnnyc2026/cms` and `@johnnyc2026/contractor-os-core` (same versions

   `_generated` output is stale the moment the move lands)

Keep `packages/backend/convex/healthCheck.ts` and `privateData.ts` as-is.

5. `grep -rn "apps/web/convex" --include="*.ts" --include="*.tsx" apps packages`

## Acceptance criteria
- `packages/backend` typechecks with the domain functions, both components
  registered, membership table in schema.
- No source file anywhere references `apps/web/convex`.
- The web app's existing `api` imports are untouched and still resolve
  (they now point at the real backend).
- No secrets committed; no `.env` value files touched.

## Out of scope
- Tenant/role enforcement beyond what exists (that's T4).
- Deploying to a Convex deployment (that's T13's runtime proof).
- Any UI changes.
