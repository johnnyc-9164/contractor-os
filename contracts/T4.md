# T4 — Tenant/role enforcement in the domain facade

## Goal
Every domain function authenticates the caller AND resolves their tenant +
role from the `contractorOsMemberships` table, and refuses cross-tenant
access. Today `cms.ts` only checks "is there an identity" and `backend.ts`
carries the header "Connect your existing authentication provider; do not
expose tenant/role arguments" — i.e. authz is unwired. After this task,
there is no unauthenticated or cross-tenant path to the domain API.

## Dependencies
T1 (the facade files live in `packages/backend/convex/` after the move).

## Context (verify in the moved files before editing)
- `packages/backend/convex/cms.ts` — `requireIdentity(ctx)` helper; every
  exported function calls it, then delegates to the CMS component.
- `packages/backend/convex/memberships.ts` — `set` is an `internalMutation`
  (owner-only; NEVER expose it publicly); the table is keyed by
  `tokenIdentifier` with a `by_identity` index; roles are
  `viewer | operator | admin`.
- `packages/backend/convex/backend.ts` — domain mutations/queries built on
  `ContractorBackend` from `@johnnyc2026/contractor-os-core`; read the file
  fully (via `graft skeleton` then the exact spans) to find where tenant
  context must enter. Tenant/role must NEVER come from client arguments.

## Files (8 max)
1. `packages/backend/convex/memberships.ts` — add an internal query
   (e.g. `getMyMembership`) resolving the caller's `tokenIdentifier` →
   `{ tenantId, role, enabled }`; keep `set` internal
2. `packages/backend/convex/cms.ts` — replace bare `requireIdentity` with a
   `requireMembership(ctx, minRole?)` helper; every function resolves tenant
   and passes it down (never trusts client-supplied tenant ids)
3. `packages/backend/convex/backend.ts` — same treatment for all 15
   mutations + 7 queries: resolve membership first, throw on missing/disabled
   membership, scope all data access to the resolved `tenantId`
4. `packages/backend/convex/schema.ts` — only if a field is genuinely
   missing for the above (prefer no schema change)
5. `packages/backend/convex/lib/authz.ts` — new, if a shared helper is
   cleaner than duplicating logic in `cms.ts`/`backend.ts`
6. `packages/backend/convex/lib/authz.test.ts` — unit tests for the helper
   (pure logic: role hierarchy, disabled membership, missing membership)
7. (optional) `apps/web/convex/auth.config.ts` location — after T1 this file
   lives in `packages/backend/convex/`; confirm Clerk JWT config is intact
8. Nothing else

## Verification (5 max)
1. `pnpm check-types` — exit 0
2. `pnpm test` — exit 0, including the new authz tests
3. `pnpm exec biome check packages/backend` — exit 0
4. `grep -rn "internalMutation" packages/backend/convex/memberships.ts`
   confirms `set` is still internal-only
5. `grep -rn "tenantId" packages/backend/convex/backend.ts | grep -v
   "args.tenantId"` — tenant ids never read from client args (spot-check;
   explain any hit in the PR body)

## Acceptance criteria
- Unauthenticated calls throw before touching any component or table.
- Disabled memberships and unknown identities are refused.
- No client argument can select or switch tenants.
- `memberships.set` remains internal; changing access still requires the
  owner path.

## Out of scope
- UI for managing memberships (no admin screen in this task).
- Row-level policies inside the core component (out of our hands — the
  facade is the enforcement point).
